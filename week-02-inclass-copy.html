3 Cycle 3: Subsetting & Mutating Vectors

3.1 Glucose Filtering and Cleaning

A metabolic health study collected fasting blood glucose levels (mg/dL) from 8 patients: glucose <- c(95, 142, 180, 88, 210, 115, -1, 104)

  1. Extract all values in the pre-diabetes range (\(100 \le \text{glucose} \le 125\)).
  2. The measurement -1 is a missing value code. Replace all negative values in glucose with NA.
  3. Extract all valid readings (\(\ge 126\), excluding NA) indicating diabetes.
glucose <- c(95, 142, 180, 88, 210, 115, -1, 104)

# 1. Pre-diabetes subset:
glucose[100 <= glucose & glucose <=125]
[1] 115 104
# 2. In-place replacement of negative values with NA:
glucose [glucose == -1] <- NA

# 3. Diabetes subset (>= 126, non-NA):
glucose [glucose >=126& !is.na(glucose)]
[1] 142 180 210

4.2 AI Corner: Spotting Vector Recycling Errors

An AI assistant was asked to calculate the Body Mass Index for 4 patients with heights (in meters) c(1.70, 1.85, 1.62, 1.78) and weights (in kg) c(65, 82).

The AI produced this code:

# AI Generated code:
heights <- c(1.70, 1.85, 1.62, 1.78)
weights <- c(65, 82)
bmi_calc <- weights / (heights^2)

4.2.1 Questions:

  1. What did R do when computing bmi_calc? Why is the result clinically invalid?
  2. How would you write a defensive check in R to prevent vector recycling when calculating BMI?

(Write your explanation and defensive check below)

When computing bmi_calc as written above, R will perform element-wise division. That is, the person with height = 1.70 will have a BMI with the weight 65; the person with height = 1.85 will have a BMI with weight = 82; the person with height = 1.62 will have a BMI with weight = 65; the person with height = 1.78 will have a BMI with the weight = 65). In short, given that the weights vector is length 2 and heights vector is length 5, R will ‘recycle’ the two values in weights so that the 2 elements of heights still have a corresponding weight for the calculation.

This is clinically invalid unless the person with height 1.62 actually has a weight = 65 and the person with the height 1.78 actually has a weight =82. Otherwise, the recycling method that R will use will assign incorrect weights for 2 people, which render incorrect BMI values.

A defensive check would be to first check if the length of the height vector is the same as the length of the weight vector:

 if (!length(heights) == length(weights)) print ("not enough info")
[1] "not enough info"
#this should print "not enough info" if the height and length vectors are NOT equivalent length.
